# OpenMarket Data API Assessment for the 15-Minute Research Pipeline

**Research date:** 2026-08-17. **Scope:** first-party OpenMarket pages and API documentation only. The supplied offering URL (`https://openmarket.xyz/20a5dbcc-1827-4e9f-ad36-b9231101f285`) returned HTTP 404 when checked; this assessment uses the live offering page and linked API docs instead.

## Verdict

OpenMarket is a plausible **complement**, not an immediate replacement, for CoinAnalyze. It can supply the current pipeline's 15-minute OHLCV, OI, funding (including predicted funding where present), and liquidation inputs on a per-venue basis. Its differentiated addition is aggressor-side volume-at-price, TPO, minute order-book snapshots, and a live raw-trade stream. The decisive caveat is retention: the documented history ceiling is 30 days on Basic, 90 days on Standard, and one year on Advanced. No first-party document found promises REST historical individual-trade replay, so it is unsuitable as the sole source for trade-level backtests unless OpenMarket confirms replay and retention in writing. [API overview](https://openmarket.xyz/docs/) [rate limits](https://openmarket.xyz/docs/rate-limits) [trade stream](https://openmarket.xyz/docs/ws/trades)

## Provider and Product

OpenMarket describes itself as a market-intelligence and execution terminal; its Terms identify the site as OpenMarket and say it is a software provider rather than an exchange, broker, or custodian. The data product is the **OpenMarket Data API**, a unified REST and WebSocket API for crypto and Polymarket data. REST uses `https://api.openmarket.xyz/v1/points`; metadata/discovery has related `/v1/*` endpoints. ## Data, Granularity, and Coverage

| Dataset | Documented form and granularity | Fit |
| --- | --- | --- |
| OHLCV | `TRADE_SIDE_AGNOSTIC_AGG`: OHLCV, first/last trade timestamps; `TRADE_AGG`: separate BUY and SELL OHLCV/volume series. Supported intervals: 1m, 5m, 15m, 30m, 1h, 4h, 1d, 1w, subject to type support. | Direct 15-minute replacement/parallel feed; per-side candles can add CVD-style features. |
| Open interest | `OPEN_INTEREST_AGG` OHLC, with fields optional when a venue does not report all values. | Direct fit, but preserve missingness rather than treating omitted OI fields as zero. |
| Funding | `FUNDING_RATE_AGG` OHLC for actual and predicted funding where available; optional fields. Funding can normalize to an 8-hour interval (default) and cross-venue aggregation is OI-weighted. | Direct fit for actual and predicted funding; verify field availability per venue/symbol. |
| Liquidations | `LIQUIDATION_AGG`, one BUY and one SELL series, bucketed by requested interval. | Direct candidate for the current 15-minute liquidation fields. |
| Volume-at-price | `VOLUME_PROFILE_AGG`: automatic price buckets, flat `[price, buyVolume, sellVolume]` triplets, 2x weight, maximum 20,000 points. TPO adds price/time blocks and profile measures; its fixed block sizes are 5, 30, 60, or 240 minutes. | Strong fit for profile features; better than inferring volume-at-price from OHLCV. |
| Order-book / liquidation depth | Minute `BLOCK_BOOK_SNAPSHOT_AGG` bid/ask price-volume pairs, configurable price bucket and depth; Hyperliquid-only liquidation and TP/SL heatmaps are Advanced. | Useful as a bounded minute-snapshot feature set, not a full book-event feed. |
| Trades | WebSocket `TRADE` emits individual trade ID, price, base amount, aggressor side, and seconds/nanoseconds timestamp. `TRADE_AGG` batches live OHLCV at configurable intervals such as 200ms, 1s, or 5s. | Suitable for collecting new trade-level data and constructing future profiles; REST docs expose aggregates, not historical individual trades. |
| Other | Advanced: Bitcoin dominance, Deribit implied-volatility summaries and skew; Polymarket discovery, candles/order book, streams, and analytics. | Outside the current perp pipeline, potentially useful for regime research. |

Sources: [candles](https://openmarket.xyz/docs/rest/candles), [OI](https://openmarket.xyz/docs/rest/open-interest), [funding](https://openmarket.xyz/docs/rest/funding-rate), [liquidations](https://openmarket.xyz/docs/rest/liquidations), [volume profile](https://openmarket.xyz/docs/rest/volume-profile), [TPO and quickstart](https://openmarket.xyz/docs/quickstart), [order-book heatmap](https://openmarket.xyz/docs/rest/orderbook-heatmap), [trade WebSocket](https://openmarket.xyz/docs/ws/trades).

**Venues and symbols.** The published IDs cover derivatives: `BINANCE_FUTURES`, `BINANCE_DELIVERY`, `BYBIT`, `OKEX_SWAP`, `OKEX_FUTURES`, `DERIBIT`, `BITMEX`, `BITGET`, `BITFINEX_DERIVATIVES`, `GATE_IO_FUTURES`, `HYPERLIQUID_FUTURES`, `HYPERLIQUID_HIP3`, `HUOBI_DM`, `HUOBI_DM_SWAP`, `HUOBI_DM_LINEAR_SWAP`, and `CME`; spot: `BINANCE`, `BYBIT_SPOT`, `COINBASE`, `OKEX`, `BITFINEX`, `GATE_IO`, `BITSTAMP`, `UPBIT`, `HUOBI`, and `HYPERLIQUID`; and `POLYMARKET`. This is an API enum, not a guarantee that every dataset exists for every market. Symbols are exchange-native `rawSymbol` values (for example Binance Futures `BTCUSDT`) paired with an exchange; `normalizedSymbol` and `coin` are alternatives. `GET /v1/markets`, `/v1/symbols`, and `/v1/coins` are zero-weight discovery calls and should be the source of the runtime mapping and availability matrix. ## History, Delivery, and Cost

Plan-limited historical depth is Free: 7 days; Basic: 30 days; Standard: 90 days; Advanced: one year. Basic/Standard/Advanced have unlimited daily weight; Free has 1,000 weight/day. The docs do not specify older archival availability, exact earliest timestamp by dataset/venue, or a historical raw-trade endpoint. Treat the stated depth as a maximum entitlement and prove coverage with pilot queries before relying on backfill. [rate limits](https://openmarket.xyz/docs/rate-limits)

REST is authenticated by `X-OpenMarket-Key`; WebSockets authenticate with `public/authenticate` and the API key. REST is a common `/v1/points` schema with `from` plus `period`; all basic 15-minute dataset types above are 1x and permit up to 100,000 points/request, except volume profiles (2x/20,000), TPO (5x/20,000), and order-book heatmaps (10x/4,000). WebSockets separate book from non-book regional endpoints and support raw trades, aggregated trades, order-book snapshots, funding, OI, liquidations, and volume profiles. [authentication](https://openmarket.xyz/docs/authentication) [WebSocket overview](https://openmarket.xyz/docs/ws/overview)

Published monthly prices and sustained weight/minute limits are: Free $0/10; Basic $99/150; Standard $199/350; Advanced $599/1,500. Burst capacity is 2x sustained. Only Advanced permits multi-exchange aggregation and the one-year history tier. API responses expose rate-limit headers and `Retry-After`; `/v1/usage` is zero weight. [rate limits](https://openmarket.xyz/docs/rate-limits)

## Architecture Fit and Recommendation

The repository runs one raw-market DuckDB writer every 15 minutes, evaluates completed bars only, and requires a 14-day 15-minute OHLCV/OI/funding backfill for a selected candidate. It currently uses CoinAnalyze aggregate-perp symbols and calls five endpoint families before upserting one consolidated `futures_data` row. [pipeline architecture](../README.md#architecture) [history requirement](../README.md#discovery-and-evaluation) [current ingestion](../ingest_coinalyze.py) [current bootstrap](../bootstrap_trend_history.py)

OpenMarket's `FIFTEEN_MINUTES` interval and per-venue OHLCV/OI/funding/liquidation responses match the cadence, but its identifiers and richer response shape require an explicit venue/symbol mapping and normalization layer. Do not substitute OpenMarket's cross-exchange candle aggregation for a price series: its documentation says `GROUP_BY_TYPE_SUM` returns only volume and first/last timestamps while OHLC are zero. Its cross-exchange aggregation also requires Advanced. [intervals and aggregation](https://openmarket.xyz/docs/exchanges#intervals) [candle constraint](https://openmarket.xyz/docs/rest/candles)

1. **Validate, no production dependency:** create an account/key, call zero-weight market/symbol discovery for the present Binance universe, and query 15-minute OHLCV, OI, funding, and liquidations for the benchmark assets. Record actual available-since dates, field completeness, timestamps, symbol mappings, and close/volume differences versus CoinAnalyze.
2. **Parallel 14-day pilot:** Basic is the minimum documented paid tier that covers the repository's 14-day bootstrap. Ingest a small, explicit per-venue set beside CoinAnalyze into separate provenance-bearing tables; do not alter strategy inputs. Test retries against `Retry-After`, late/missing bars, and whether 150 weight/minute covers the chosen universe.
3. **Add differentiated features only after parity:** materialize 15-minute aggressor buy/sell volumes and periodic volume profiles; retain raw WebSocket trades only for newly collected data and bound their storage. Evaluate them in point-in-time research before changing signals.
4. **Upgrade only for a demonstrated need:** use Advanced if one-year OpenMarket backfill or vendor-side cross-exchange aggregation is required. Keep CoinAnalyze or venue-native data as the historical fallback until coverage and data-quality checks pass. Obtain written confirmation if historical trade replay, dataset-specific retention, SLA, or licensing is required.
