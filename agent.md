# Research Analyst — Agent Guide

## Mission

This repository is a discovery + strategy-evaluation engine for crypto USDT
perpetuals. It turns warmed market data into two portable outputs:

1. **Advisory alpha events** — falsifiable directional theses delivered to Discord
   (and historically Telegram). Research-only; never an order.
2. **Trade-intent envelopes** — `schema_version=1` JSON consumed by
   `bybit-executor` over a shared file inbox. The executor owns sizing, venue
   selection, and execution.

```text
Analyst:  market data -> discovery -> strategy eval -> alpha event (advisory)
                                                 \-> trade intent (executor inbox)
Executor:                                         intent -> risk -> sizing -> order -> lifecycle
```

An alpha event / intent must be a directional thesis with an entry condition,
invalidation, targets, and expiry. A ticker, discovery rank, indicator count, or
LLM narrative alone is never alpha.

## Ownership Boundaries

**Analyst owns**
- Point-in-time discovery, the static/rotated universe, local market-data history.
- Canonical asset, direction, setup class, phase, entry condition, invalidation,
  targets, expiry, feature snapshot, and research confidence.
- Event validation, the advisory ledger, Discord delivery, and the executor
  trade-intent outbox (what to trade, not how big).

**Executor (bybit-executor) owns**
- Venue/instrument mapping, current tradeability, liquidity, executable cost.
- **Sizing and leverage** (from its account profile `risk.risk_amount`).
- Duplicate/portfolio-conflict handling, order choice, retries, position lifecycle.
- Any order placement. This repository never stores exchange credentials or submits
  orders.

The trade intent carries **no** `quantity` / `risk_amount`. Sizing is executor-owned.

## Runtime Topology

| Process | Owns | Status |
| --- | --- | --- |
| `ws_gateway` | WebSocket ingestion: Bybit (on) / Binance (off), 1m+5m streams, resample 15m/1h/4h from 5m; **sole writer of `source_observations`** | Online |
| `orchestrator` | Strategy evaluation, pruning, rotation feed, PM sidecar, intent delivery; **sole writer of `DB_PATH`** | Online (research/active) |
| `binance-oi-rotation-scanner` | OI rotation discovery + feed, membership TTL, hard prune | Online if rotation used |
| `pm_sidecar` | Emit-only hold/exit/reduce advice (`pm_advice`) | Disabled by default |
| `signal-publisher` | Legacy advisory delivery (pre-WS) | Stopped / superseded |

`ws_gateway` and `orchestrator` must never run as duplicate writers of the same
table. `config.py` is the schema/migration entrypoint.

## Data, Universe & Discovery

- **Static universe:** `symbols/static_universe.json` — 97 bases (nautilus
  `CRYPTO_STATIC`), generated by `config.load_static_symbols()`. Canonical bases
  (e.g. `BTC`); `expand_perp_symbols(base, venue)` → `BTCUSDT`.
- **Rotation [optional]:** `WS_SYMBOL_SOURCE ∈ {static, rotated, both}`. Active
  `binance_oi_rotation_*` members are exported by `rotation_feed.py` to
  `BINANCE_OI_ROTATION_FEED_PATH`; `ws_gateway` consumes them. Gated by
  `ROTATION_FEED_ENABLED` + `WS_SYMBOL_SOURCE=rotated|both`.
- **Ingestion:** `ws_gateway` streams `1m`+`5m` kline + markPrice and resamples
  `15m/1h/4h` from the 5m base. Bars are stamped `data_purity=pure_ws`. The emit
  gate accepts any `pure_*` purity; non-pure history is not used for deterministic events.

## Strategy Evaluation

Strategies are **plugins** registered by `STRATEGY_ENABLED_IDS` (which exist) and
runtime-enabled by `STRATEGY_ACTIVE_IDS` (which are live; empty = all enabled).
Each plugin is an independent hypothesis.

| Plugin | Hypothesis |
| --- | --- |
| `accumulation-base-v2` | 1h compression + limit at 1h EMA99 with confluence score |
| `impulse-ignition-v2` | Armed breakout of 1h base lid (not a chase post-breach) |
| `continuation-breakout-v2` | 4h trend + 1h flag breakout (`armed_flag_breakout`) |
| `rsi-reclaim-v1` | 4h bias + 1h EMA200 extension + 15m RSI pullback/turn reclaim |
| `liquidity-sweep-reversal-v1` | PDH/PDL sweep reversal (opt-in) |
| `*-v1` legacy (accumulation/ignition/continuation) | Retired — registered but inactive by default |

Evaluation runs on `EVAL_INTERVALS` (`1m,5m,15m`); HTF `1h`/`4h` are enrichment
only (bias, swings, ATR). Every evaluator cuts off at the completed bar boundary
for its interval and queries strictly earlier bars.

## Event Contracts

### Advisory alpha event (`alpha_outbox`)
Atomic, deduplicated JSON in `data/alpha_outbox/`. Identity =
`strategy_id|asset|direction|observed_at`; `alpha_id`/`dedupe_key` deterministic.

```text
schema_version, alpha_id, strategy_id, asset, direction (long|short),
setup_class, phase, observed_at, valid_until, horizon_minutes, confidence,
entry_condition {type, price}, invalidation_price, targets[], feature_snapshot,
dedupe_key, (data_purity, price_source, plugin_version, input_snapshot_id)
```

`confidence` is score-derived, `confidence_status='uncalibrated'` (not a
calibrated probability). Statuses: `active`, `expired`, `invalidated`.

### Executor trade intent (`intent_outbox` → `INTENT_INBOX`)
When `INTENT_DELIVERY_ENABLED=true`, every accepted event also emits a
`schema_version=1` TradeIntent envelope to the shared inbox the executor polls
(contract: `bybit-executor/AGENTS.md` "Trade Intent Contract"). Mapping:

| Executor field | Source |
| --- | --- |
| `delivery_id` | `alpha_id` (executor journal dedupes replays) |
| `source` | `INTENT_SOURCE` (`research-analyst`) |
| `exchange_id` / `account_id` | `INTENT_EXCHANGE_ID` / `INTENT_ACCOUNT_ID` |
| `asset` / `symbol` | `asset` / `to_ccxt_perp_symbol` → `BTC/USDT:USDT` |
| `direction` | `long|short` → `LONG|SHORT` |
| `order_type` | `INTENT_ORDER_TYPE` (`limit` IOC default, or `market`) |
| `entry_price` | `entry_condition.price` (null when `market`) |
| `stop_loss` | `invalidation_price` |
| `take_profit` | `targets[0]` |
| `take_profit_mode` | `INTENT_TAKE_PROFIT_MODE` |
| `observed_at` / `entry_valid_until` | ISO Z; expiry = `valid_until` else `observed_at + INTENT_VALIDITY_MINUTES` |
| `metadata` | non-sizing only — **no quantity/risk_amount** |

Admission is validated before delivery: geometry must be valid, limit entries must
meet `INTENT_MIN_RR` (default 2.0), and SL distance must be between
`INTENT_MIN_STOP_DISTANCE_PCT` and `INTENT_MAX_STOP_DISTANCE_PCT` (defaults 0.1%
and 5%). Invalid events are skipped (the advisory event still emits). The executor
sizes from its account profile — the analyst never sends size.

## Executor Integration (no guessing)

### Compact Strategy Ports

The compact-mode ports are restricted to `BTC`, `ETH`, `PAXG`, and `QQQ` only.
`failed-break-v3` and `bb-rsi-meanrev-v1` execute on 5m bars;
`williams-fractal-scalp-v1` executes on 1m bars; and
`ema9-continuation-stochrsi-v1` uses a 5m setup with a 1m trigger. These IDs are
opt-in through `STRATEGY_ENABLED_IDS`; they do not evaluate the general universe.

Their alpha events use the unchanged TradeIntent contract, including SL geometry
and minimum 2R admission. A TA target above 2R is preserved; a target below 2R
remains advisory-only and is not delivered to the executor.

The analyst **writes** `INTENT_INBOX`; `bybit-executor` **reads** the same path.
Set one knob and the shared path resolves automatically:

```bash
# .env — point at the executor repo root
BYBIT_EXECUTOR_DIR=/home/ubuntu/bybit-executor
INTENT_DELIVERY_ENABLED=true
```

`INTENT_INBOX` then defaults to `<BYBIT_EXECUTOR_DIR>/data/intents` — exactly the
executor's own default inbox. If the executor overrides its `INTENT_INBOX`, set
the analyst's `INTENT_INBOX` to that same absolute path. Sizing is executor-owned;
do not add `quantity`/`risk_amount` to the analyst intent.

The PM sidecar reads executor 1m snapshots and also writes the executor's *PM
Decision Contract* (`POSITION_DECISION_DIR` files: `HOLD`/`REDUCE`/`EXIT`). A PM
`HOLD` can veto a discretionary strategy exit, but cannot override the executor's
protective SL or fixed TP. The initial TP remains at least 2R; runner/trailing
management is an executor-side concern.

**Per-strategy routing (multiple accounts/exchanges).** `INTENT_ROUTING` is a JSON
map keyed by `strategy_id` that overrides `exchange_id` / `account_id` (and
optionally `order_type`, `take_profit_mode`, `validity_minutes`, `source`) per
strategy. Strategies not listed fall back to the `INTENT_*` defaults. This makes
e.g. `impulse-ignition-v2` → `bybit/account_y` while `rsi-reclaim-v1` →
`binance/account_b` possible from one analyst process. Distinct `delivery_id`s keep
the executor profiles independent. The executor must have each referenced
`exchange/account` configured in `EXECUTION_ACCOUNTS_JSON`.

## Operations

```bash
cp .env.example .env
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python config.py          # create tables / apply migrations
./venv/bin/python ws_gateway.py &        # ingestion (single writer)
./venv/bin/python orchestrator.py        # eval + delivery loop
```

Set `DISCORD_ALPHA_WEBHOOK_URL` for advisory signals. For executor delivery set
`BYBIT_EXECUTOR_DIR` and `INTENT_DELIVERY_ENABLED=true` as above. `./venv/bin/python
orchestrator.py --once` runs one evaluation cycle.

When an expected event/intent is absent, inspect in order: universe/discovery
state → `source_observations` freshness → plugin active flags
(`STRATEGY_ACTIVE_IDS`) → evaluator outbox file → `alpha_events` →
`INTENT_INBOX` files.
